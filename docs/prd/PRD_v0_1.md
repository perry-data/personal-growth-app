# 个人成长系统（本地优先）PRD v0.1（初版）

- 文档状态：Draft
- 版本：0.1.0
- 最后更新：2026-01-13
- 负责人：默小
- 目标平台：Flutter Desktop（macOS / Windows），后续扩展移动端

---

## 1. 背景与问题

你想要的不是“打卡表”，而是一个能**把生活数据变成可理解的反馈**的系统：

- 记录不应只停留在“我做了什么”，而应回答“**什么在影响我**”“**哪些行为组合更让我状态好**”。
- 需要同时容纳：客观数据（睡眠/运动/学习时长）与主观感受（心情/压力/精力）。
- 需要轻量、顺手、可复盘，而不是复杂配置与长表单。
- 当前阶段：**先让自己用得爽**，不做登录/账号体系，不做多人，不做云同步优先。

---

## 2. 产品目标与非目标

### 2.1 目标（Goals）

G1. 形成最小闭环：**今天记录 → 看到状态变化 → 复盘获得启发 → 下次更愿意记录/调整**  
G2. 以“**特质水桶**”作为核心可视化：水位代表分数/状态，直观、可对比、可回看。  
G3. 本地优先、低摩擦：无需登录；打开就能用；离线可用；数据不丢。  
G4. 能产生“启发”而不只是统计：提供**趋势、对比、简单关联提示**（不做玄学）。

### 2.2 非目标（Non-goals）— v0.1 不做

N1. Auth/账号、云端同步、多端一致性冲突处理  
N2. 社交、排行榜、公开分享  
N3. 复杂 AI 诊断/建议（先做基于数据的可解释提示）  
N4. 大而全的第三方集成（可在 v0.2+ 逐步加）

---

## 3. 目标用户与使用场景

### 3.1 目标用户（单人）

- 自我优化型用户：希望把“状态”变成可量化、可复盘的系统
- 对“可视化反馈”敏感：希望一眼看到自己在哪些维度变好了/变差了
- 不想被流程打断：讨厌登录、授权、复杂配置

### 3.2 核心场景

S1. 每天晚间 30 秒：记录心情/精力 + 打几个标签（例如：奶茶、熬夜、健身）  
S2. 白天随手：完成某个习惯/任务，或记录时长/次数  
S3. 周末复盘：看特质水桶的水位变化 + 找到“高状态日”的共同点  
S4. 状态异常：最近焦虑/效率低，想快速找可能相关的因素（熬夜、咖啡、运动缺失等）

---

## 4. 产品范围（v0.1 功能清单）
>
> 重点：先把“记录→水桶→复盘→启发”做顺，功能宁少勿散。

### 4.1 核心模块

M1. 今日（Today）

- 今日概览：日期、总览状态（心情/精力/压力三选一或两项）
- 今日习惯/任务：勾选/计数/时长
- 今日标签：一键添加（自定义）
- 快速记录：1~2 次点击完成

M2. 特质水桶（Traits Buckets）

- 多个水桶卡片（例如：健康、精力、专注、社交、情绪稳定、自律等）
- 每个水桶显示：当前水位、今日变化（+/-）、7天趋势
- 进入详情：水位曲线 + 贡献来源（哪些记录/习惯推动水位变化）

M3. 复盘（Review）

- 7天/30天视图
- 高水位日/低水位日自动挑选（Top 3 / Bottom 3）
- “可能相关因素”提示（基于统计关联/共现，不做强因果）

M4. 数据字典（Data Points）

- 允许用户创建“数据点”并选择类型：
  - 数值（如学习时长、步数、摄入水量）
  - 计数（如咖啡杯数）
  - 等级（1-5 或 1-9：心情/压力/精力）
  - 标签（发生/未发生：如奶茶、熬夜、社交、健身）
- 数据点可绑定到：某个水桶（影响权重）、或仅用于复盘分析

## 5. 关键体验设计（MVP 体验准则）

P1. **30 秒原则**：完成一次“今日记录”≤ 30 秒  
P2. **不逼迫**：缺失数据允许；用空状态引导而不是报错  
P3. **反馈先于功能**：每次记录都能立刻看到水位变化/趋势  
P4. **解释性**：任何“提示/关联”必须可点开看到依据（数据点与样本数）  
P5. **视觉核心是水桶**：水位变化是最主要的情绪奖励

## 6. 详细需求

### 6.1 今日（Today）页面

### 必备

- 今日状态打分（可选项）：心情/精力/压力（默认 1-5）
- 今日标签：自定义标签，支持一键复用最近使用
- 今日习惯：最少支持“勾选型”（完成/未完成）
- 保存后即时反馈：至少触发相关水桶水位变化动画

### Should

- 快捷入口：+1 次、+10 分钟、+一杯咖啡（用户可配置快捷按钮）
- 晚间提醒（本地通知，先不做复杂策略）

### 6.2 特质水桶（核心）

#### 6.2.1 水桶定义

- 水桶=一个“特质维度”
- 水位范围：0~100（默认）
- 水位变化来源：
  - 手动打分（例如心情/精力）
  - 习惯完成（+）
  - 负向标签（-）
  - 数值数据点（按规则映射）

#### 6.2.2 水位计算（v0.1 简化版）

- 采用“日增量”模型：每天根据记录计算 Δ，然后累计到水位（并做衰减/上限）
- 默认规则：
  - 正向习惯完成：+a
  - 负向标签出现：-b
  - 等级评分：映射到 [-c, +c]
- 必须支持：用户在“水桶设置”中调整权重（高级选项，可藏在设置里）

### 必备（今日页面）

- 水桶列表（卡片）：名称、水位、今日 Δ、7日趋势
- 水桶详情：30天曲线 + “贡献清单”（哪些记录导致变化）

### 可选（水桶体验增强）

- 水位变化动画：水面上升/下降
- 水桶颜色/图标自定义（轻量）

### 6.3 复盘（Review）

### 复盘必备功能

- 7天/30天总览：每个水桶趋势
- Top/Bottom 天：展示当日标签、习惯完成情况
- 关联提示（简单版）：
  - 标签共现：高水位日常见标签/习惯
  - 均值对比：有/无某标签时的平均心情/精力

#### Should（复盘增强）

- 支持筛选：只看某个水桶、只看工作日/周末
- 支持“假设检验提示”（弱化呈现）：样本过少时提示“不足以判断”

## 8. 数据模型（本地优先）
>
> v0.1：本地 SQLite（Drift 或等价方案），不引入登录与云端。

### 8.1 核心表

- `day_log`
  - date (YYYY-MM-DD)
  - mood_score (nullable)
  - energy_score (nullable)
  - stress_score (nullable)
  - note (nullable)

- `tag`
  - id, name, color(optional), created_at

- `day_tag`
  - date, tag_id

- `habit`
  - id, name, type(enum: check/count/duration), is_active, created_at

- `habit_entry`
  - date, habit_id, value (bool/int/minutes), updated_at

- `bucket`
  - id, name, target_range(0-100), order, created_at

- `bucket_rule`
  - bucket_id
  - source_type(enum: habit/tag/score/datapoint)
  - source_id
  - weight (float)
  - mapping (json: 规则参数)

- `bucket_snapshot`
  - date, bucket_id, level(0-100), delta, computed_at

### 8.2 导出/备份

- Export：一键导出 `userdata_YYYYMMDD.json`
- Import：支持导入并合并（v0.1 可先做覆盖导入）

## 9. 关联/洞察（Insights）策略（v0.1）
>
> 原则：提示“可能相关”，不声称因果；必须展示依据（样本数/对比值）。

### 9.1 v0.1 能做的洞察

- 标签/习惯与评分的对比：
  - 例：有“熬夜”标签的日子，平均精力评分比无熬夜低 X（n=…）
- 水桶高低日对比：
  - 高水位日最常出现的 3 个标签/习惯
- 趋势提醒：
  - 连续下降 3 天的水桶提示“是否需要复盘？”

### 9.2 约束

- 样本数 < 7：只显示“数据不足”
- 只做一元对比（v0.1 不做多变量回归）

---

## 10. 非功能性需求

- 性能：打开首页 < 1s（本地数据规模 2 年以内）
- 稳定：本地崩溃不丢数据（写入采用事务）
- 隐私：默认本地存储；不上传；导出需用户主动
- 可维护：规则/水桶/数据点都可配置，不写死在 UI

## 11. 里程碑（建议）

### Milestone 0：骨架与本地数据（1-2 天）

- Today / Buckets / Review / Settings 页面骨架
- SQLite 表结构 + 基础 CRUD（习惯、标签、日记）

### Milestone 1：特质水桶 MVP（3-5 天）

- 水桶列表 + 详情曲线
- 规则系统（习惯/标签/评分 → 水位 Δ）

### Milestone 2：复盘与洞察（3-5 天）

- 7天/30天视图

## 12. 风险与对策

R1. 水桶规则过复杂导致难用  

- 对策：默认规则足够好；高级设置隐藏；给“推荐模板”（健康/专注等）

R2. 洞察变成“玄学结论”  

- 对策：只做对比与共现；强制展示样本数；措辞统一为“可能相关”

R3. 记录摩擦太高导致弃用  

- 对策：30秒原则；最近标签/快捷按钮；默认最少字段
